# NIRIKSHAN-X

NIRIKSHAN-X is a production-style Government Project Monitoring & Resolution System. Its public portal follows the supplied Government of India visual reference; its officer workspace uses a real Express API, PostgreSQL database, Prisma schema, JWT-cookie authentication, role checks, audit trails, evidence metadata and a deterministic risk engine.

## Architecture

`React + Vite client → REST API → Express controllers/routes → services → Prisma → PostgreSQL`

The risk engine executes on the server whenever progress, milestones or issues change. An OpenAI-compatible analysis layer is optional and clearly reports when it falls back to the deterministic engine.

## Stack

- Client: React, TypeScript, Vite, Tailwind CSS, TanStack Query, React Hook Form + Zod, Recharts, Leaflet.
- Server: Node.js, Express 5, TypeScript, Prisma, PostgreSQL, Zod, JWT, bcrypt, Multer, Swagger.
- Deployment: Docker Compose, PostgreSQL service, independent client and server images.

## Local installation

1. Copy `.env.example` to `.env` and set secrets (never use the defaults in production).
2. Start PostgreSQL, for example `docker compose up -d db`.
3. Run `npm install` from this directory.
4. Run `npm run db:generate`, `npm run db:migrate` (or `npm run db:push` for a disposable local database), and `npm run db:seed`.
5. Run `npm run dev`. The public client is at `http://localhost:5173`; API docs are at `http://localhost:4000/api/docs`.

Use `npm run build` for production builds, `npm run start` for the compiled API, and `npm run test` for the tests.

## Docker

After creating `.env`, use `docker compose up --build`. The compose development service synchronizes the Prisma schema with `db push` and runs the idempotent initial seed, so it starts cleanly without a pre-generated migration. The portal is published on port 8080 and the API on 4000; the bundled Nginx configuration proxies `/api` and `/uploads` to the backend service.

## Security and access

- Access and refresh JWTs are sent in HTTP-only cookies; passwords are bcrypt-hashed.
- RBAC is checked by Express middleware, not merely by UI visibility.
- Helmet, CORS, rate limiting, JSON size limits, Zod validation and Prisma parameterisation are enabled.
- Evidence MIME type and size are checked server-side; executables are rejected.
- Audit logs are server-created and limited to administrators.
- The public routes return only approved/public project data, public updates and public evidence metadata.

## Environment settings

See `.env.example` for `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, client/server URLs, storage and S3 settings, OpenAI settings, and SMTP settings. Local storage uses `server/uploads`; the storage boundary is isolated for a future S3 adapter. If SMTP is absent, email events are logged as unsent development events; no false-delivery claim is made.

## Operational flows

- Project CRUD, milestones, issues, progress updates and evidence records persist through PostgreSQL routes.
- A progress update writes a project update and audit entry, then recalculates risk and status.
- Critical issues create notifications for administrators and update risk.
- Public grievances receive a generated tracking ID and can be securely tracked without exposing internal notes.
- CSV and PDF reports are generated by the API from current PostgreSQL records.
